AGENT WORKFLOW BACKEND API CONTRACT
==================================

This document defines the contract expected by the frontend so the backend team can implement the APIs accurately.

BASE URL
--------
Production or staging base URL should follow:

https://api.example.test/api/v1

If the application is running locally in the same domain, the backend may also expose these under:

/api/v1

HTTP standard:
- JSON API responses: Content-Type: application/json
- SSE stream: Content-Type: text/event-stream

COMMON RESPONSE FORMAT
----------------------
Success:
{
  "success": true,
  "data": { ... }
}

Error:
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "Human readable message",
    "requestId": "req_123456",
    "details": []
  }
}

2) POST /workflows/validate
---------------------------
Purpose:
Validate graph before starting execution.

Request body:
{
  "nodes": [
    {
      "id": "business-analyst-1",
      "type": "agentNode",
      "data": {
        "agentType": "business-analyst",
        "label": "Business Analyst",
        "prompt": "Analyze requirements."
      }
    },
    {
      "id": "devforce-1",
      "type": "agentNode",
      "data": {
        "agentType": "devforce",
        "label": "DevForce",
        "prompt": "Implement the approved requirements."
      }
    }
  ],
  "edges": [
    {
      "id": "edge-1",
      "source": "business-analyst-1",
      "target": "devforce-1"
    }
  ]
}

Success response:
{
  "success": true,
  "data": {
    "valid": true,
    "issues": [],
    "executionOrder": ["business-analyst-1", "devforce-1"]
  }
}

Failure response:
{
  "success": true,
  "data": {
    "valid": false,
    "issues": [
      {
        "severity": "error",
        "code": "CIRCULAR_DEPENDENCY",
        "message": "Circular connections are not supported.",
        "nodeIds": ["business-analyst-1", "devforce-1"]
      }
    ],
    "executionOrder": []
  }
}

Validation rules expected by frontend:
- At least one node is required.
- Each node must use a supported agent type.
- Prompt must be non-empty.
- Source/target nodes in every edge must exist.
- No duplicate edges.
- No self-references.
- No circular dependencies.
- Exactly one Start and one End boundary node required.
- Start node cannot have incoming edges.
- End node cannot have outgoing edges.
- Every execution node must be reachable from Start and must reach End.

SSE STREAM CONTRACT
-------------------
Purpose:
Push real-time workflow execution status to the frontend.

Event stream endpoint:
GET /runs/:runId/events

Response type:
text/event-stream

Event format:
{
  "type": "node.started",
  "runId": "run_abc123",
  "eventId": "evt_123",
  "sequence": 1,
  "timestamp": "2026-08-30T12:00:00.000Z",
  "nodeId": "business-analyst-1",
  "status": "running",
  "attempt": 1,
  "startedAt": "2026-08-30T12:00:01.000Z"
}

Supported event types:
- stream.ready
- run.queued
- run.started
- node.queued
- node.started
- stage.started
- stage.completed
- log
- node.completed
- node.failed
- run.completed
- run.failed
- run.stopped
- heartbeat

Important frontend expectations:
- Each event should be sent as an SSE event with JSON payload.
- Events must include a unique eventId and monotonic sequence number.
- Terminal events are expected to close the stream: run.completed, run.failed, run.stopped.
- The client reconnects automatically if connection breaks.
- If lastEventId is provided on reconnect, backend should continue from that point.

Example SSE message:

event: node.started
id: evt_123
retry: 1000

data: {"type":"node.started","runId":"run_abc123","eventId":"evt_123","sequence":1,"timestamp":"2026-08-30T12:00:00.000Z","nodeId":"business-analyst-1","status":"running","attempt":1,"startedAt":"2026-08-30T12:00:00.500Z"}

EDGE CASES AND ERROR HANDLING
----------------------------
The frontend expects these common error codes:
- WORKFLOW_VALIDATION_FAILED
- RUN_NOT_FOUND
- MOCK_ROUTE_NOT_FOUND
- INVALID_API_RESPONSE
- INVALID_SSE_EVENT

Always return a consistent error envelope with:
- code
- message
- requestId
- optional details[]

SECURITY NOTES
--------------
- Tokens should never be returned in GET or list endpoints unless explicitly required.
- In the current app, tokens are stripped before mock responses for test and save calls.
- Real backend should store tokens securely and never expose them in plain-text responses.

FINAL NOTES
-----------
- The frontend currently uses a mock adapter by default, but the contract above is the expected production-ready format.
- The backend team can implement the APIs and stream in this shape without changing the frontend contract.
- If the backend uses a different base path, the frontend can be updated through environment config using NEXT_PUBLIC_API_BASE_URL.
